# Stage A v6: Seven-Loss Background-Aware Sparse PSF Unmixing

Stage A v6 is trained independently after the G0 image-only baseline. It
accepts only a normalized infrared image `I` and returns five full-resolution
maps:

- `B`: spatially varying background;
- `S`: non-negative sparse source, factorized as presence probability `P`
  times centroid amplitude `A`;
- `T_psf`: explicit PSF response generated by applying a constrained,
  spatially mixed anisotropic Gaussian kernel bank to `S`;
- `R`: non-PSF target residual;
- `U`: reconstruction uncertainty from a single sigmoid head (no longer
  blended with PSF-mixture entropy as in v5).

The reconstruction contract is `I ~= B + T_psf + R`. Masks are used only to
construct weak training targets and evaluation diagnostics; they are not
model inputs.

## What changed since v5

The full design rationale lives in
`docs/superpowers/specs/2026-09-07-a-v6-7loss-design.md`. Three structural
differences from v5:

1. **Eight-term loss with all weights 1.0.** v5's ten-term loss included
   terms that duplicated each other (the v5 `target` + `residual` pair
   both reduced to "do not let target energy leak outside support") and
   terms whose effect was indistinguishable (`bg` mixed image-fidelity
   with TV). v6 collapses to eight physics-named addends: `rec`, `bg`,
   `sp`, `ctr`, `psf`, `ind`, `flip`, `amp`. The only non-unit
   coefficients are two engineering constants: `rec` upweights target
   support by 5x, and `psf` uses a 0.1 usage-entropy coefficient.

2. **Public `U` is single-construct.** v5 mixed 0.75·u_rec + 0.25·psf_entropy
   in the public output while only supervising u_rec with the loss. The
   result was a Spearman correlation against reconstruction error of −0.21.
   v6 public `U = sigmoid(uncertainty_head(features))` exactly; psf_entropy
   is exposed only as an aux diagnostic.

3. **Explicit h-flip equivariance on P and A.** v5 had no paired-flip
   constraint; the v5 S horizontal-flip Pearson was 0.78. v6 runs a
   second forward on `flip(I, dims=[-1])` per training step and adds a
   `flip` loss term that penalises non-equivariant P/A outputs.

4. **Geometric `ctr_local` for the XDU9-class failures.** v5 had five
   IRSTD-1K samples (XDU9, XDU999, XDU733, XDU302, XDU167) where
   `centroid_recall=0` but `presence_at_centroid=1.0` — the network
   found *a* highlight near the true centroid but mislocated it by more
   than 5 px. v6's `ctr` adds a 11x11 max-pool over sigmoid(p_logits),
   `stride=1, padding=5`, gated by the true-centre mask. It forces
   *at least one* true centre to have a strong local maximum.

## Experiment scope

This is a method-exploration run with seed 42. It measures checkpoint,
perturbation, and cross-domain stability, but does not establish stability
across random initializations. v5 dual-source reduced the public `S`
density failure and tightened target-energy calibration; v6 must in
addition fix the v5 public-`U` Spearman failure, the h-flip correlation
failure, and the geometric mislocation failure. Passing v6 means that
the decomposition is interpretable enough to freeze for G1–G5. It does
not mean that A has already improved segmentation.

Only the original 800-image IRSTD-1K training split is used: 720 train
and 80 deterministic validation samples. The 201-image test split never
selects a checkpoint.

SIRST4 is reported as two subsets because its 201 `XDU*` test images
duplicate the IRSTD-1K test set. `sirst4_non_xdu` is the cleaner
cross-domain result.

## Remote environment

Use a Python environment where the CUDA build of PyTorch is already
installed. Do not install a CPU-only PyTorch wheel over it.

```bash
cd /path/to/new_model_v3
python -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.get_device_name(0))"
python -m pip install -r requirements-a.txt
```

The expected device is one NVIDIA RTX 4090 with 24 GB memory.

## One consolidated preflight and GPU smoke run

The smoke directory is timestamped to prevent overwriting an earlier run.

```bash
cd /path/to/new_model_v3
set -euo pipefail

python -m pytest -q tests
python -m compileall -q irstd_a train_a.py eval_a.py visualize_a.py configs/a_psf_irstd1k.py

SMOKE_DIR="runs/a_psf/debug/smoke_v6_$(date +%Y%m%d_%H%M%S)"
python train_a.py \
  --config configs/a_psf_irstd1k.py \
  --run-dir "$SMOKE_DIR" \
  --device cuda --debug --limit-train 8 --limit-val 4 --epochs 2

python eval_a.py \
  --checkpoint "$SMOKE_DIR/a_best.pt" \
  --run-dir "$SMOKE_DIR" \
  --datasets irstd1k sirst_uavb sirst4 \
  --limit 4 --probe-count 2 --device cuda

python visualize_a.py \
  --checkpoint "$SMOKE_DIR/a_best.pt" \
  --metrics "$SMOKE_DIR/per_image_metrics.csv" \
  --output-dir "$SMOKE_DIR/visualizations" \
  --max-panels 8 --device cuda

echo "SMOKE_DIR=$SMOKE_DIR"
tail -n 20 "$SMOKE_DIR/log.txt"
```

All tests must pass; both training epochs must remain finite; peak
allocated memory must remain below 24 GB; and the smoke directory must
contain best/last checkpoints, metrics, stability JSON, CSV, component
panels, and a PSF sheet. The v6 train log header should show eight
addends (`rec`, `bg`, `sp`, `ctr`, `psf`, `ind`, `flip`, `amp`) — not
the v5 ten-term header.

## Formal exploratory training

Run only after the consolidated smoke output and visual panels have been
reviewed. The console log is a sibling of the run directory so
`train_a.py` can enforce an initially empty formal directory.

For a paid remote GPU, the preferred single command performs the CUDA
check, the complete test suite, compilation, training (or automatic
resume), evaluation, visualisation, v6 acceptance-gate reporting, and
artifact packaging without idle hand-offs:

```bash
cd /path/to/new_model_v3
bash run_a_v6_remote.sh
```

Override `RUN_DIR`, `CONFIG`, `DEVICE`, or `SEED` as environment variables
only when intentionally creating a different experiment.

```bash
cd /path/to/new_model_v3
set -euo pipefail
mkdir -p runs/a_psf
RUN_DIR="runs/a_psf/irstd1k_seed42_v6_sevenloss"
```

## v6 acceptance gate

The `metrics.json` produced by `eval_a.py` includes a
`coverage_at_5px_gate` entry next to the v5 `degeneration_flags`. v6
adds the following IRSTD-1K test gates to the v5 list:

- `coverage_at_5px_mean >= 0.85` (the new XDU9-class fix);
- `uncertainty_error_spearman_median >= +0.30` (v5 = −0.21);
- h-flip S Pearson median ≥ 0.90 (v5 = 0.78), reported in
  `stability.json` under `perturbation.hflip.S.pearson.median`.

The v5 gates remain binding: target-output energy precision ≥ 0.80,
target-contrast recall ∈ [0.50, 2.00], source false activation ≤ 0.20,
centroid recall near 1.0, background target leakage ≤ 0.30,
PSF/residual overlap ≤ 0.50, residual target fraction ≤ 0.50, no
collapse flags.

The cross-domain expectation is unchanged: numerical or component-energy
collapse fails v6; plain low numbers do not.

## Result interpretation

The main quantitative artifacts are `metrics.json`, `stability.json`,
`per_image_metrics.csv`, and the `visualizations/` directory. Review
them together with every selected nine-panel image:

`I | Y | B | S | T_psf | R | U | reconstruction | absolute error`.

If `B` visibly retains targets, `R` copies the image, or `S` follows
cloud edges, revise v6 before starting G1–G5. Visual evidence overrides
a misleading aggregate.
